Original Requirement Text (Jira STLC-512)
Title: SuperApp 5G Charging Event Notification Middleware

Description:
The 5G network charging core must broadcast real-time event notifications for credit thresholds, top-up receipts, and session updates to the SuperApp Middleware. This enables immediate user interface notifications and real-time ledger syncing.

Acceptance Criteria:
- OCS must broadcast notifications within 50ms.
- Event messages must adhere strictly to JSON schemas.
- Failure delivery attempts must trigger up to 3 retry attempts.
AI Proposed Improvement Draft (V2)
Enhanced Title: e& SuperApp 5G OCS Mediation Real-Time Balance & Event Notification System
Detailed Description:
The 5G core Online Charging System (OCS) mediation engine must establish a low-latency gRPC stream and fallback REST webhook pipeline to dispatch transaction state event notifications (pre-paid balance warning, post-paid charging alerts, session top-up events) to the e& SuperApp Middleware. This ensures zero ledger lag and triggers real-time subscriber screen messages.
Missing Negative/Boundary Acceptance Criteria Added:
  • Boundary System must handle concurrent load spikes of up to 120,000 TPS under peak weekend call volume without drops.
  • Negative If SuperApp endpoint returns 503 Service Unavailable, OCS must buffer the notifications queue inside Redis cache for up to 3 hours.
  • Data Spec Event payloads must contain fully qualified MSISDN (E.164 format) and ISO-4217 currency codes.
